# 广州一日游手机 App 化、百度导航与真实照片设计

日期：2026-08-01  
状态：已确认设计，等待规格审阅

## 目标

在不登录、不请求定位、不引入百度地图密钥的前提下，解决当前地图加载不稳定的问题，并把现有广州情侣一日游网页优化为更适合手机当天使用的旅行工具。

完成后应满足：

- 手机端使用“路线／地图／待办／我的”四栏底部导航，每栏显示独立主窗口。
- 桌面端继续保留适合出发前浏览和对比的完整长页面。
- 页面不再加载 Leaflet 或 OpenStreetMap 瓦片，国内网络下不会出现地图无限加载或空白。
- 页面内路线图始终可用；查看真实地图和导航时统一调起百度地图。
- 使用 8–9 张允许再利用的真实照片，覆盖主要景点和美食，并在站内保留作者、来源与许可信息。
- 保留现有场景切换、预算对比、预约清单和本机打卡数据。

## 已确认约束

- 不申请或使用百度地图 AK。
- 不将百度地图网页强行放入 `iframe`，避免跨域、嵌入限制和移动端兼容问题。
- 不再请求任何第三方地图瓦片。
- 不使用 AI 生成图冒充真实景点或美食照片。
- 不使用不明版权图片，不远程热链图片。
- 不实现账号、云同步、定位、推送或原生 App 安装。
- 生产环境继续使用 GitHub Pages：`https://z-xq7.github.io/guangzhou-day-trip-0820/`。

## 总体方案

采用渐进式手机 App 壳：同一套结构化行程数据驱动手机功能页与桌面长页面。手机端通过底部导航切换功能；桌面端按当前顺序展示完整内容，不强制用户逐页切换。

页面由以下边界清晰的模块组成：

- `TripPlanner`：组合共享数据、场景和持久化状态。
- `MobileAppShell`：管理手机端当前功能和底部导航。
- `RouteView`：当前站、下一站、场景切换、时间轴和照片。
- `RouteDiagram`：本地 HTML/CSS 路线图及站点选择。
- `TodoView`：预约清单、不可妥协的时间节点和完成度。
- `MyTripView`：完成度、预算、当前模式、核验日期、来源与清除记录。
- `StopDetail` 与 `StopPhoto`：可在手机和桌面复用的站点详情与照片。

这些模块只通过 `ItineraryStop`、当前场景、选中站点和本机状态通信。地图实现、照片加载或手机导航结构可以独立调整，不改变行程数据规则。

## 手机信息架构

### 路线

- 首屏展示日期、当前站、下一站时间和下一站百度导航。
- 正常／下雨／高铁晚点切换置于首屏可见区域。
- 时间轴显示全部有效站点、完成状态、交通方式和预计到达时间。
- 选择时间轴站点后在同一主窗口展开详情、对比和真实照片。
- 站点详情继续展示预算、预约、必看、必吃和横向方案比较。

### 地图

- 主画面为本地 HTML/CSS 路线图，不是地理比例地图，并明确标注“游览顺序示意”。
- 路线图展示广州南、西关、越秀、天字码头等区域关系，以及有效站点编号、时间和连接顺序。
- 点击站点后更新下方站点摘要；在时间轴选择站点时同步高亮路线图。
- 提供“在百度地图查看地点”和“百度地图去下一站”两个明确操作。
- 雨天与晚点模式会重新计算可见站点和编号，不保留已被删减节点的空位。

### 待办

- 展示去程高铁、返程高铁、陈家祠门票、珠江夜游、天气与停航五项清单。
- 显示完成数量与百分比。
- 保留 07:45 前抵穗、18:50 到码头、21:40 后返程三个硬时间点。
- 办理入口保持官方渠道；完成状态只保存在当前设备。

### 我的

- 展示已完成站点数、待办完成数、当前场景和双人预算区间。
- 展示信息最后核验日期。
- 展示景点、美食、地图和图片来源说明。
- 提供“清除本机记录”，执行前显示二次确认；确认后只清除场景、打卡、待办和最近功能，不影响页面内容。
- 明确说明“不登录、不定位、不上传数据”。

## 桌面端

- 保留现有完整长页面和页面内锚点导航。
- 使用同一套 `RouteDiagram`、百度地图按钮、站点照片和来源信息。
- 不显示手机底部导航，不把桌面内容拆成隐藏标签页。
- 当前固定“下一站”操作条可以保留，但导航名称和链接改为百度地图。

## 百度地图设计

百度地图官方 JSAPI 和当前静态图 API 均要求 AK；无密钥 URI API 允许网页或移动浏览器调起百度地图。因此本项目采用“本地路线图 + 百度 URI”的组合，而不在页面内声称展示百度底图。

新增 `buildBaiduMapUrl`：

- 目的地使用结构化地点名称，例如“广州 陈家祠”。
- 当前项目不请求用户位置；起点使用上一站地点名称，第一站使用“广州南站”。
- `walk` 映射为步行，`bus` 映射为公交，`car` 映射为驾车。
- 生成的 URL 使用百度地图 URI API 支持的 UTF-8 编码。
- 所有外链保持 `target="_blank"` 和安全的 `rel` 属性。
- 若浏览器不能调起百度 App，百度网页仍可根据地点名称显示结果。
- 复制地点按钮把“广州 + 地点名称”写入剪贴板；若剪贴板权限失败，展示可手动复制的文本。

移除内容：

- `leaflet` 运行时依赖和延迟加载逻辑。
- `public/assets/leaflet.css`。
- OpenStreetMap 瓦片与署名。
- 地图加载超时状态和旧 SVG／Leaflet 回退分支。

## 真实照片

页面配置 9 个照片位：

1. 广式早茶或经典点心。
2. 陈家祠建筑与岭南装饰。
3. 泮塘五约或荔枝湾涌。
4. 永庆坊或粤剧艺术博物馆。
5. 宝华路代表性西关小吃。
6. 沙面建筑群。
7. 北京路千年古道。
8. 大佛寺夜景或建筑。
9. 珠江夜游与广州塔夜景。

照片选择规则：

- 优先 Wikimedia Commons 的公有领域、CC BY 或 CC BY-SA 文件；需要署名时完整保存作者、原文件页和许可名称。
- 可使用明确允许项目再利用的政府或机构开放图片；普通官网宣传图不因公开可见而默认可复制。
- 若某一照片位没有合规且清晰的候选，改用同站点另一真实主题，不使用来源不明图片补位。
- 图片下载到 `public/images/stops/`，转为 WebP；单张目标不超过 180 KB，长边不超过 1600 像素。
- 首屏照片使用高优先级，其余 `loading="lazy"`、`decoding="async"`。
- 统一使用 3:2 或 4:3 裁切；保留主体，不在照片上写无法核验的信息。
- 每张图片有描述性中文 `alt`；纯装饰裁切不重复朗读。
- 图片卡片提供站点名称和“真实照片”标识；加载失败时显示同尺寸文字占位卡。

`ItineraryStop` 增加可选 `photo` 字段，包含本地路径、替代文字、作者、来源页和许可。图片署名在站点详情中简短展示，并在“我的／来源”中集中列出。

## 状态与导航

`TripState` 升级到版本 2，新增最近手机功能 `activeView`：`route | map | todo | me`。

- 从版本 1 恢复时保留场景、站点打卡和待办，只补默认 `activeView: "route"`。
- 手机首次进入默认显示路线；之后恢复最近功能。
- 点击底部导航同步更新 URL 锚点 `#route`、`#map`、`#todo`、`#me`。
- 浏览器前进／后退会切换对应功能，不产生重复历史记录循环。
- 桌面端锚点继续滚动到真实内容区域。
- 切换场景时，如果当前选中站点被删减，自动选择第一个有效游览站点。

## 响应式与无障碍

- 手机断点沿用 `760px`。
- 底部栏包含 `env(safe-area-inset-bottom)`，正文下方留白大于导航实际高度。
- 所有按钮、标签和站点标记触控区域至少 44×44px。
- 底部导航使用可理解的文本和 CSS 图形，不依赖仅图标表达。
- 当前功能使用 `aria-current="page"`；功能主窗口有对应标题。
- 键盘可依次访问功能导航、路线站点、百度操作和待办。
- 尊重 `prefers-reduced-motion`，功能切换不使用大幅滑动动画。
- 手机和桌面均无横向滚动。

## 失败处理

- 页面不依赖地图脚本或瓦片，因此不再存在地图持续加载状态。
- 本地照片失败时展示文字占位，不隐藏站点详情。
- 百度地图调起失败时保留复制地点按钮和可读地点名称。
- 本机状态解析失败时回到版本 2 默认值，不阻止页面显示。
- 清除记录只在用户二次确认后执行。

## 非目标

- 页内可缩放的百度地图。
- GPS 实时定位或附近推荐。
- 自动计算当天实时路况与精确交通耗时。
- 账号、情侣共享编辑、云同步或社交功能。
- App Store／Android 安装包。
- AI 生成景点或食物照片。
