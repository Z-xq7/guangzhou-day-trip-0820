# 广州全域 OpenStreetMap 互动地图设计规格

**日期：** 2026-08-17

**状态：** 设计已获用户确认，待规格复核

**目标页面：** `#discover`（发现广州）

## 1. 背景与问题本质

当前发现页已经有 30 个景点与美食的结构化坐标、编号和本地照片，但地图是固定的 1440×900 OpenStreetMap 衍生图片。它适合建立大致方向感，却无法同时满足以下需求：

- 在广州全域尺度看清所有地点的相对分布；
- 放大到街道、建筑和地图地标；
- 在密集的荔湾、越秀区域准确选中地点；
- 直观看到两个地点相距多远。

根因是单张静态图片只有一个比例尺。解决方案不是继续提高图片分辨率，而是让用户按需加载不同缩放级别的地图瓦片，并保留静态图片作为失败回退。

## 2. 已确认目标

把发现页的静态总览升级为网页内可缩放的 OpenStreetMap：

1. 显示广州全域，并允许平移、缩放到街道和地标层级；
2. 标注现有 30 个景点与美食，编号与地点卡片保持一致；
3. 点击标记可查看地点摘要，并与现有详情卡片双向联动；
4. 可选两个地点，计算并显示直线距离；
5. 移动端仍可顺畅操作；
6. 地图网络加载失败时，完整内容和静态地图仍然可用。

## 3. 非目标与边界

- 不接入百度地图、高德地图或其他导航服务；
- 不提供步行、公交、驾车路线，也不把直线距离描述为实际路程；
- 不申请或保存任何地图 API Key；
- 不请求浏览器定位，不采集、上传或保存用户位置；
- 不预下载地图瓦片，不制作离线广州瓦片包；
- 不新增或猜测景点；本期地图只展示已经核验的 30 个地点；
- 不删除一日游路线页既有的百度导航按钮，本次变更只负责发现页地图；
- 发现页地点卡片中的既有资料来源链接保持不变。

## 4. 技术决策

### 4.1 地图引擎与底图

- 使用 Leaflet 1.9.x 在客户端渲染地图；不使用远程脚本 CDN；
- 使用 OpenStreetMap Standard raster tiles：`https://tile.openstreetmap.org/{z}/{x}/{y}.png`；
- 地图右下角始终显示并可点击 `© OpenStreetMap contributors`；
- 地图容器下方继续显示“地图需联网加载，位置与距离仅供行程比较”的说明；
- 瓦片 URL 封装为单一配置常量，未来切换合规供应商时无需改组件逻辑。

选择理由：OSM 无需账号或 API Key，能提供用户需要的街道和地标层级；Leaflet 体积小、支持键盘标记、瓦片、弹窗、缩放和平移，适合 GitHub Pages 静态部署。

### 4.2 渐进增强与失败回退

服务端和首屏 HTML 先渲染现有本地静态地图、图例和编号地点表。客户端进入可视区域后再动态加载 Leaflet：

1. 至少一张首屏瓦片成功加载后，交互地图淡入；
2. Leaflet 模块加载失败或首屏瓦片全部失败时，静态地图保持可见；
3. 回退状态显示“实时地图暂不可用”，并提供“重试加载”按钮；
4. 不因单张瓦片失败切走整个地图，避免偶发网络错误造成闪烁；
5. 断网时照片、地点介绍、评分、筛选和静态地图仍可使用。

静态底图不是隐藏的占位图，而是交互地图的可靠底座。这保证 JavaScript 失败、OSM 暂不可用或用户离线时页面仍有完整信息。

### 4.3 依赖边界

- 新增 `leaflet` 与 TypeScript 类型；
- 使用轻量 Leaflet 聚合插件处理全城尺度的密集点位，插件代码随站点构建，不从 CDN 加载；
- 不引入 React 地图封装层，地图实例由一个小型客户端适配器管理，减少 SSR/Vite/Vinext 双构建差异；
- 使用自定义 HTML 圆形标记，不依赖 Leaflet 默认 PNG 图标路径。

## 5. 地图范围与比例尺

### 5.1 初始视图

- 初始视图自动适配 30 个地点的经纬度边界，并保留足够边距；
- 该视图让用户第一眼看到所有可选目的地的相对分布；
- 提供“全部地点”控制，任何时候可恢复这个范围；
- 提供“广州全域”控制，显示广州市行政区域的大致完整范围，帮助理解从中心城区到外围目的地的方向关系；
- 不锁死地图边界，用户可继续平移查看相邻区域。

### 5.2 缩放层级

- 低缩放级别用于全城方向和点位分布；
- 中缩放级别显示区级道路与地标；
- 高缩放级别显示街道、建筑和更细地标；
- 最大缩放不超过底图实际支持范围，避免虚假放大；
- 鼠标滚轮缩放默认关闭，点击地图后可通过明确的缩放控件或触控手势操作，避免页面滚动被意外劫持。

“完整地图”指可按需浏览 OSM 当前覆盖的广州地图数据，而不是把所有街道同时挤在一张图片里。

## 6. 点位、聚合与详情联动

### 6.1 标记

- 01–21 为榕绿景点标记，22–30 为朱砂美食标记；
- 标记显示两位编号，与详情卡和无障碍地点表一致；
- 可点击区域不小于 44×44 CSS 像素；
- 当前地点使用清晰的描边和 `aria-current`/`aria-pressed` 状态；
- 所有标记使用 `DiscoveryPlace.coordinate`，不复制第二套坐标数据。

### 6.2 密集点位

- 全城和城区级别自动聚合相邻标记；
- 聚合标记显示其中地点数量；
- 点击聚合标记放大到该组范围；
- 达到街道级别后显示单个标记；坐标完全重叠时使用蜘蛛展开，避免地点永久不可点。

### 6.3 地图弹层

点击单个标记后显示紧凑弹层，包含：

- 编号、名称、行政区、类型；
- 3:2 本地实景照片；
- 站内推荐分与一句简介；
- “查看完整介绍”按钮；
- “设为距离起点”或“与此地点比较”按钮。

弹层不展示导航按钮或外部地图入口。

### 6.4 与现有卡片双向联动

- 地图标记 → 更新现有 `selectedPlaceId`，并允许用户打开对应详情卡；
- 地点卡“在地图查看” → 地图平移/缩放到标记、展开弹层并把键盘焦点交给标记；
- URL 中现有 `#discover/<place-id>` 状态继续可刷新和前进/后退；
- 地图缩放和平移不写入 URL，避免产生大量浏览历史记录。

## 7. 两点距离比较

### 7.1 操作模型

1. 用户点击任一地点并选择“设为距离起点”；
2. 地图进入比较状态，提示“再选一个地点”；
3. 用户选择第二个地点后显示距离结果；
4. 起点和终点使用 A/B 标识及连接虚线；
5. 用户可以互换两点、重新选择或清除比较。

### 7.2 距离口径

- 使用 Haversine 公式根据两个 WGS84 经纬度计算球面直线距离；
- 小于 1 公里显示到 0.1 公里，大于等于 1 公里显示到 0.1 公里；
- 结果固定注明“直线距离，不代表步行、驾车或公共交通里程”；
- 不调用远程路线服务，也不推算通勤时间。

### 7.3 状态生命周期

- 比较中的两个地点只保存在组件会话状态；
- 刷新页面后清空，不写入 `localStorage`；
- 筛选不会删除已选择的比较地点；若地点不在当前筛选结果中，距离面板仍显示其名称并明确说明。

## 8. 页面结构与移动端体验

### 8.1 桌面端

- 地图保持宽幅主视觉，地图高度足以显示街道标签；
- 图例、地图状态和全域/全部地点控制位于地图上方；
- 距离比较面板位于地图右侧或下方，不遮挡 OSM 署名；
- 地图弹层宽度限制在可读范围，不覆盖大面积地图。

### 8.2 移动端

- 地图采用接近设备视口的高度，但不被底部应用导航遮挡；
- 全部控件触控区域至少 44×44；
- 距离面板放在地图下方，不用覆盖式抽屉遮挡地图；
- 聚合和弹层可用单指点击，地图支持双指缩放；
- 页面在 320、375、390 像素宽度下无横向滚动；
- 支持 `prefers-reduced-motion`，关闭非必要淡入和平移动画。

## 9. 可访问性

- 地图容器有清楚的中文名称和操作说明；
- 标记可通过 Tab 聚焦并用 Enter/Space 激活；
- 距离结果通过 `aria-live="polite"` 宣读；
- 颜色之外同时使用编号、类型文字和 A/B 标识；
- 静态编号地点表始终保留，作为键盘、读屏和地图失败时的等价入口；
- 弹层关闭后焦点返回触发标记；
- OSM 署名不被遮挡、不折叠到隐藏区域。

## 10. 隐私、授权与网络约束

- 只请求用户当前视口需要的瓦片；
- 不预取广州全域的多层级瓦片，不提供“下载离线地图”；
- 遵守瓦片响应的浏览器缓存策略，不发送绕过缓存的请求；
- 正常浏览器请求保留有效 Referer；
- 可见署名链接到 OpenStreetMap 版权页；
- 页面说明地图加载会向 OpenStreetMap 请求瓦片，但不会发送本站保存的清单或个人信息；
- OSM 瓦片服务没有 SLA，因此本地静态回退是必需能力，而非可选优化。

## 11. 数据与文件结构

保持 `DiscoveryPlace.coordinate` 为唯一点位来源，新增逻辑按职责拆分：

- `src/features/discovery/discovery-distance.ts`：Haversine 计算与显示格式；
- `src/features/discovery/osm-map-adapter.ts`：Leaflet 初始化、瓦片、标记、聚合、视图控制；
- `src/features/discovery/DiscoveryMap.tsx`：React 状态、渐进增强、距离面板与无障碍语义；
- `src/features/discovery/DiscoveryMapPopup.tsx`：地点弹层内容；
- `app/globals.css`：地图、弹层、比较面板及响应式样式；
- `public/images/discovery/guangzhou-overview-map.webp`：继续作为本地回退底图。

地图适配器通过回调向 React 报告选中地点、瓦片成功/失败和视图变化，React 不直接依赖 Leaflet 内部 DOM。

## 12. 测试与验收

### 12.1 单元测试

- 相同坐标距离为 0；
- 用已知坐标验证 Haversine 结果误差；
- 距离格式的公里单位与舍入；
- A/B 选择、互换、清除状态；
- 30 个坐标均为有限数且位于合理广州范围。

### 12.2 组件测试

- 服务端/初始渲染包含静态地图、30 个编号地点和 OSM 署名；
- Leaflet 成功时显示交互地图状态；
- 模块或瓦片失败时保留静态地图并可重试；
- 点击标记打开地点弹层并调用现有选择回调；
- 详情卡可把地图定位到指定标记；
- 两点选择显示名称、A/B 连线和直线距离声明；
- 地图弹层中不存在百度、高德或导航按钮。

### 12.3 构建与产物测试

- Vinext 与 GitHub Pages 两种构建均成功；
- 产物包含本地 Leaflet 代码和静态回退图；
- 不包含远程脚本 CDN、百度或高德地图 SDK；
- 允许且仅允许配置中的 OSM 瓦片主机；
- 生产 HTML 保留静态地图、地点列表和版权署名。

### 12.4 浏览器验收

在 320×568、375×812、390×844 和 1440×900 验证：

1. 地图加载并可拖动、缩放；
2. 初始范围包含全部 30 个地点；
3. 放大后能看到街道和地图地标；
4. 聚合点可展开，单点可打开弹层；
5. 从地图打开详情、从详情回到地图均正确；
6. 两点比较结果正确，清除后状态复位；
7. 浏览器前进、后退和刷新仍恢复地点选择；
8. 断网刷新时静态地图和全部资料仍可读；
9. 页面无横向滚动，底部应用导航不遮挡操作；
10. 控制台无未处理错误，OSM 署名始终可见。

### 12.5 完成标准

- 用户在两次点击内能从任一地点卡定位到地图标记；
- 用户在 30 秒内能比较任意两个地点的直线距离；
- 地图放大后可辨认街道和 OSM 地标；
- OSM 不可用时页面不会出现空白地图；
- 不需要账号、API Key、定位权限或新的用户配置。
