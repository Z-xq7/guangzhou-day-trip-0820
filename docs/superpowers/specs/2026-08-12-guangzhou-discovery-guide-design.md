# 广州「发现」城市指南设计规格

日期：2026-08-12  
状态：用户已确认（2026-08-12）
目标版本：在现有广州情侣一日游网页中新增「发现广州」，保留原有路线、地图、待办和我的功能。

## 1. 问题与目标

现有网页回答的是“8 月 20 日这一天怎么走”，但无法回答“广州还有哪些地方值得去、不同地点如何比较、下次怎么选”。新功能必须把广州的代表性景点和餐饮压缩成一份可浏览、可筛选、可收藏、可定位的城市指南。

成功标准：

- 首屏 10 秒内能看懂“广州最值得去什么”；
- 任一地点两次点击内看到照片、评分、介绍和地图位置；
- 30 秒内能按情侣、亲子、长辈、室内、免费等条件筛出候选；
- 不登录、不申请定位，也不依赖运行时地图服务；
- 所有实景照片、评分与营业信息均可追溯，未知信息明确标注未知。

## 2. 已确认范围

- 受众：情侣优先，同时提供亲子与长辈适合度。
- 数量：30 个精选地点，不做无边界景点百科。
- 内容：景点与具体餐厅均纳入，支持分类型筛选。
- 版式：A 方案——杂志式发现页；大图负责建立兴趣，卡片与筛选负责决策。
- 地图：本地静态地图图片，清晰标注编号与大致位置；不嵌入在线地图。
- 外部导航：每张卡片保留百度地图地点或路线链接。
- 数据：设备本地收藏，不登录、不上传、不采集定位。

## 3. 信息架构

手机底部主导航改为：

`路线｜发现｜地图｜待办｜我的`

- 路线：保留现有 8 月 20 日情侣一日游主线。
- 发现：新增 30 个地点的城市指南，是本次主要功能。
- 地图：保留现有一日游路线示意；发现页内另有 30 点静态总览地图。
- 待办、我的：保留现状。

桌面端仍使用同一页面与 URL hash，不另建后台或多页站点。`#discover` 可直接进入发现页；地点详情使用 `#discover/<id>`，浏览器前进、后退和刷新必须可恢复状态。

## 4. 发现页结构

### 4.1 导览头图

- 标题：“30 个地方，读懂广州的古今与烟火气”。
- 一句话说明：情侣优先的编辑精选，同时标注亲子、长辈和雨天适合度。
- 4–6 张重点大图卡：西关、城市地标、岭南园林、夜景、粤味、主题乐园。
- 每张大图直接跳到对应地点详情。

### 4.2 搜索、筛选与排序

- 搜索：名称、别名、区域、标签、招牌菜。
- 类型：全部、景点、美食。
- 主题：岭南文化、历史古迹、情侣拍照、城市地标、博物馆、自然、夜景、主题乐园、早茶、粤菜、小吃甜品。
- 区域：荔湾、越秀、海珠、天河、白云、番禺及其他。
- 场景：情侣、亲子、长辈、雨天、夜间。
- 成本：免费、低消费、中消费、高消费。
- 排序：编辑推荐、情侣适合、亲子适合、预计耗时、预算。
- 已选条件以可删除标签展示；无结果时解释冲突条件并提供“清除筛选”。

### 4.3 地点卡片

折叠卡片最少显示：

- 真实实景照片、名称、类型和区域；
- 站内推荐分与一句话推荐理由；
- 2–3 个关键标签；
- 建议停留、预算区间；
- “查看详情”“想去”“百度地图”。

展开详情增加：

- 120–180 字原创介绍；
- 必看/必吃、最佳时段、建议停留、交通提示；
- 营业或开放信息及最后核验日期；
- 情侣、亲子、长辈、雨天四项适合度；
- 附近可顺路组合的地点；
- 照片作者、来源、许可及修改说明；
- 信息来源链接。

### 4.4 静态地图总览

- 使用一张本地保存的广州静态底图，显示珠江、主要城区和区名。
- 30 个地点使用与卡片一致的编号；景点与美食用两种颜色。
- 默认避免重叠；西关等密集区域使用局部放大框。
- 点击编号滚动并聚焦对应卡片；点击卡片中的“在总览图查看”则滚动到地图并高亮编号。
- 明示“位置示意，非导航地图”；底图若基于 OpenStreetMap 数据，必须显示完整署名。
- 地图图片本地加载，断网仍可查看；精确路线通过百度地图外链完成。

### 4.5 想去清单

- “想去”状态写入带版本号的 `localStorage`。
- `localStorage` 不可用时退回内存状态，本次会话仍可使用。
- 清单支持按地点类型查看、逐项删除、全部清空。
- 可将景点加入现有路线候选，但不自动改写已确认的一日游时间表；页面只提示“已加入候选”。

## 6. 评分体系

### 6.1 站内推荐分

站内分为编辑决策工具，不冒充平台用户评分。满分 5.0，保留一位小数，并在“评分说明”中公开维度。

景点权重：

- 广州特色 30%
- 体验完整度 25%
- 情侣氛围与出片 20%
- 交通与安排便利 15%
- 性价比 10%

餐饮权重：

- 广府代表性 30%
- 招牌产品完成度 25%
- 双人用餐体验 20%
- 到达与排队成本 15%
- 性价比 10%

每项基础值为 1–5；总分由数据函数计算，禁止在界面中另写一个手工总分。景点与餐饮只做各自类别内排名，不用同一个榜单直接比较。

### 6.2 平台参考分

- 只有公开页面可访问、能确认地点匹配、评分值与核验日期时才显示。
- 必须同时显示平台名、分值、满分、核验日期和原始链接。
- 无法稳定核验时显示“暂无可核验平台分”，不得推测或用搜索摘要代替。
- 平台分不参与站内推荐分计算，避免口径混淆。

## 7. 数据模型

新增独立数据域，不把 30 个发现地点硬塞进一日游 `ItineraryStop`：

```ts
type DiscoveryKind = "attraction" | "food";

interface DiscoveryPlace {
  id: string;
  index: number;
  kind: DiscoveryKind;
  name: string;
  aliases: string[];
  district: string;
  coordinate: { lat: number; lng: number };
  mapLabelOffset?: { x: number; y: number };
  summary: string;
  description: string;
  themes: string[];
  recommendedFor: string[];
  indoorOutdoor: "indoor" | "outdoor" | "mixed";
  bestTime: string;
  durationMinutes: [number, number];
  budgetPerPerson: [number, number];
  priceLevel: "free" | "low" | "medium" | "high";
  highlights: string[];
  nearbyPlaceIds: string[];
  baiduPlaceName: string;
  photo: LicensedPhoto;
  editorialDimensions: EditorialDimensions;
  platformRating?: VerifiedPlatformRating;
  sources: SourceRef[];
  verifiedAt: string;
}
```

数据校验在测试中强制：恰好 30 条、编号连续、ID 唯一、经纬度有效、评分维度完整、照片许可完整、相邻地点 ID 存在、外链使用 HTTPS。

## 8. 图片与版权

- 只使用真实地点或真实菜品照片，不使用 AI 图片伪装实景。
- 首选 Wikimedia Commons；其次为明确允许网页使用的官方开放素材。
- 餐厅若无可授权的门店照片，可使用同类真实菜品照片，但必须写明“菜品示意，非该门店实拍”，不得造成门店出品背书。
- 图片下载到 `public/images/discovery/`，转为 WebP；列表懒加载，首屏重点图预加载。
- 每张图记录作者、原始文件页、许可名称、许可链接、裁切/缩放/转码说明。
- 卡片缩略图采用 3:2；不得通过固定最小高度破坏比例。
- 图片缺失或解码失败时显示地点名与类别纹样，不影响文字和操作。
- 目标：单张不超过 280 KB，首屏图片总量不超过 900 KB。

## 9. 数据来源与更新策略

优先级：

1. 景区、博物馆、餐厅官方页面或官方公众号可公开访问页面；
2. 广州市文化广电旅游局、广州市政府及区政府；
3. 文化和旅游部、国家文物局等权威名录；
4. 仅用于补充体验判断的可靠旅游平台。

页面显示总核验日期；开放时间、票价、预约方式等易变字段单独显示核验日期。无法确认的内容不写死，改为“出发前以官方当天公告为准”。官方文旅资料已覆盖广州十大景区、西关 Citywalk、代表性老字号与非遗小吃，可作为首版选点依据。

## 10. 技术实现边界

- 继续使用现有 React、TypeScript、Vite/Vinext 静态站点结构。
- 新增 `src/data/discovery.ts`、`src/features/discovery/`，原行程数据与发现数据分离。
- URL hash 仍由单一状态所有者管理，避免导航组件与内容组件互相抢写历史。
- 发现筛选写入 URL 查询式 hash，收藏写入本地存储；刷新可恢复当前页和详情。
- 不增加地图 SDK、服务端、数据库、账号体系或定位权限。
- GitHub Pages 继续作为对外生产发布目标；现有 Sites 构建配置保留兼容。

## 11. 异常与降级

- 离线：30 个地点、照片、地图、筛选、收藏均可用；百度地图和来源链接提示需要联网。
- 本地存储异常：降级为会话内存，不弹阻断式错误。
- 图片失败：显示同尺寸占位，保留署名入口。
- 筛选无结果：解释当前条件并允许一键清空。
- 外链不可用：不影响站内详情，用户可复制地点名。

## 12. 测试与验收

### 自动测试

- 数据：30 条完整性、编号、分类、坐标、预算、评分公式、来源、图片许可。
- 逻辑：搜索、组合筛选、排序、空结果、分类内排名。
- 状态：收藏持久化与 `SecurityError` 降级；hash 直达、后退、刷新。
- 组件：地图编号与卡片双向联动、详情开合、百度链接编码、图片失败降级。
- 资源：30 张 WebP 可解码、尺寸与 3:2 比例、文件大小、许可清单一致。

### 浏览器验收

- 320×568、375×812、390×844、1440×900 无横向滚动。
- 触控目标至少 44px；底部导航不遮挡列表操作。
- 首屏重点图、筛选、30 张卡片、静态地图、署名均可达。
- 浏览器前进、后退、刷新与直接 hash 访问正确。
- 断网后站内内容与本地图片仍可浏览。
- 控制台无 error；Lighthouse Accessibility ≥95、Performance ≥85。

## 13. 非目标

- 不提供实时拥挤度、实时排队、实时票价或用户评论抓取。
- 不伪造大众点评、小红书或百度口碑分。
- 不自动生成完整多日行程，不替换已确认的一日游主线。
- 不嵌入需要密钥、Cookie 或位置权限的在线地图。
- 不做登录、云同步、评论发布或社交分享后台。
